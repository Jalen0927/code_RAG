# 项目现存边界短板

## 短板1：用户明确指定目标文件提问时，仍有可能无法召回该文件内关键分片
**现象**：当其他文件的 Cross‑Encoder 重排打分显著更高时，即便开启点名文件加权、同文件邻域扩充等启发式策略，仅依靠重排后分数微调，依然无法把目标文件内语义得分劣势的分片送入最终 Top‑N 上下文。

**典型案例**：查询 `registry.py` 里面注册机制如何实现、查询 `file_tools.py` 中全部工具函数，目标文件后半段核心分片无法进入最终结果。

**本质原因**：后处理加权仅能做偏好引导，不能强行逆转重排模型本身的相关性判断。

**潜在优化方向**：可增加名额预留机制、同文件分片软关联召回等策略进一步缓解该问题。

## 短板2：无文件名提示的开放式提问场景，缺少引导时容易召回“关键词沾边但不含答案”的分片
**现象**：用户没有指明文件名称，进行开放式业务提问，点名加权策略无法触发，完全依赖原生多路召回+重排。部分仅包含业务导入、启动逻辑、配置参数的文件（`main.py`、`config.py`、`state.py` 等），因文本内高频出现问题相关关键词，更容易被重排打出高分抢占 Top‑3 位置，但分片内部并不包含问题真正需要的答案信息。

**典型案例**：提问 `这个agent依靠哪些工具来完成文件操作？`，召回结果全部落在启动、状态、配置文件，没有命中存放工具注册与工具实现的 `registry.py`、`file_tools.py`。

**本质原因**：当前链路缺少问题意图识别、业务关键词路由等上层引导逻辑，召回仅停留在文本表层语义匹配。

**潜在优化方向**：可增加简单的问题意图识别、业务关键词路由模块，对高频业务问题做定向召回增强。
